# PostMessageClient

`PostMessageClient` sends [LTI postMessage](https://www.imsglobal.org/spec/lti-cs-pm/v0p1) requests from
your tool (running in the LMS's iframe or a window it opened) to the platform, and resolves with the
platform's matching `*.response` message. [`PlatformStorage`](./PlatformStorage.mdx) and
[`ResizeIframe`](./ResizeIframe.mdx) are built on it.

## Creating a client

```ts
import { PostMessageClient } from "@atomicjolt/lti-client";

const client = new PostMessageClient({
  origin: "https://canvas.instructure.com",
  timeout: 5000,
});
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `origin` | `string` | `"*"` | The platform's origin. Used as the target origin of outgoing messages, and only responses from this origin are accepted. With `"*"`, responses from any origin (except `"null"`) are accepted. |
| `targetFrame` | `Window \| string \| null` | `null` | Where to send messages. A `Window` is used as-is; a string names a frame in the parent window (`"_parent"` means the parent itself). With `null`, the frame is taken from the platform's `lti.capabilities` response for the message's subject, falling back to the parent. |
| `timeout` | `number` | `2000` | Milliseconds to wait for a response. |

Every option can also be overridden per request (see [`send`](#send)).

:::tip
Use a specific `origin` in production. `"*"` accepts a response from any page that knows the subject and
message ID.
:::

## `send`

```ts
send<Request extends PostMessageRequest, Response extends PostMessageResponse>(
  payload: Request,
  options?: Partial<PostMessageClientOptions>
): Promise<Response>;
```

Posts `payload` to the target frame and waits for a message whose `subject` is
`` `${payload.subject}.response` `` and whose `message_id` matches. Give every request a unique
`message_id`; [`messageId`](#messageid) generates one.

```ts
const response = await client.send({
  subject: "lti.get_data",
  message_id: client.messageId("lti.get_data", "theme"),
  key: "theme",
});
```

Override options for a single request:

```ts
await client.send(payload, { timeout: 10_000, targetFrame: "post_message_forwarding" });
```

## Errors

`send` rejects with a `PostMessageError`:

| `error.type` | When | Useful fields |
| --- | --- | --- |
| `PostMessageErrorType.Timeout` (`"timeout"`) | No response arrived within `timeout`. | `error.payload`: the request |
| `PostMessageErrorType.ResponseError` (`"response_error"`) | The platform responded with an `error`. | `error.response.error.code`, `error.response.error.message` |

```ts
import { PostMessageError, PostMessageErrorType } from "@atomicjolt/lti-client";

try {
  await client.send(payload);
} catch (error) {
  if (error instanceof PostMessageError && error.type === PostMessageErrorType.Timeout) {
    console.error("The platform didn't respond in time");
  } else if (error instanceof PostMessageError) {
    console.error("Platform error:", error.response?.error?.code, error.response?.error?.message);
  } else {
    throw error;
  }
}
```

## Capabilities

The platform lists the message subjects it supports in response to `lti.capabilities`.

```ts
// All supported messages: [{ subject: "lti.get_data", frame: "post_message_forwarding" }, ...]
const capabilities = await client.getCapabilities();

// One capability, or null if the platform doesn't support it
const putData = await client.getCapability("lti.put_data");
if (putData) {
  console.log("Platform storage is handled by frame:", putData.frame);
}
```

`getCapabilities` always asks the parent window (or `window.opener`) with origin `"*"`, regardless of the
client's options.

## `messageId`

```ts
messageId(subject: string, ...parts: string[]): string;
```

Builds a message ID from the subject, any extra parts and a random suffix:

```ts
client.messageId("lti.get_data", "theme"); // "lti.get_data-theme-k3j9x2a1b"
```
