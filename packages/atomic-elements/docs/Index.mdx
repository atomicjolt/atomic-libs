# Introduction

`@atomicjolt/atomic-elements` is Atomic Jolt's React component library: buttons, inputs, selects,
date pickers, tables, modals, layout primitives and the design tokens behind them. It is the shared
UI layer for Atomic Jolt apps, so an app built with it looks and behaves like the others.

The components are built on [React Aria](https://react-spectrum.adobe.com/react-aria/index.html) and
[React Stately](https://react-spectrum.adobe.com/react-stately/index.html), which supply keyboard
handling, focus management, ARIA semantics and internationalization. Styling uses
[styled-components](https://styled-components.com/) and CSS custom properties, so every color, size
and spacing value can be changed from a theme or from plain CSS.

```tsx
import { ElementsProvider, Button, TextInput } from "@atomicjolt/atomic-elements";

export function App() {
  return (
    <ElementsProvider applyDefaultStyles>
      <TextInput label="Course name" />
      <Button onPress={() => alert("Saved")}>Save</Button>
    </ElementsProvider>
  );
}
```

## Where to find what

The documentation is split across two sites:

| Site | Use it for |
| --- | --- |
| **These docs** | Setup, theming, and guides on concepts that span many components: fields and forms, layout and style props, collections, routing, accessibility, localization. |
| **[Storybook](https://atomicjolt.github.io/atomic-libs/storybook/)** | Reference for each component: live examples, every prop with its type and default, and the CSS variables it reads. |

If you want to know _how a component's props work_, go to Storybook. If you want to know _how the
pieces fit together_, stay here.

## Principles

- **Consistency.** Apps share the same inputs, buttons and modals instead of each keeping its own
  slightly different copy. Moving between Atomic Jolt codebases should feel familiar.
- **Fix it once.** A bug fix or improvement lands in one package, and every app picks it up by
  updating the dependency.
- **Accessible by default.** Components handle labelling, focus and keyboard interaction for you.
  When a component needs something from you to be accessible (for example an `aria-label` on an
  icon-only button), its Storybook page says so. See [Accessibility](./Guides/Accessibility.mdx).
