# Composition vs. props

Most inputs in Atomic Elements come in two forms. `TextField` and `TextInput`, for example, both
render a labelled text input:

- `TextField` is a **composition** component. You render its parts (`Label`, `Input`, `Message`,
  `ErrorMessage`) as children, in whatever order and layout you want.
- `TextInput` is a **props** component. It is built on `TextField`, renders the parts in a fixed
  layout, and takes their content as props (`label`, `message`, `error`).

Both have the same accessibility behavior. The difference is how much of the markup you control.

## Props API

The props API covers the common case in one line. It also offers layout options the composition
API would make you build yourself, such as the `floating` label variant.

<Example>
  <Example.Rendered>
    <TextInput
      label="Label"
      message="Message"
      size="full"
    />
  </Example.Rendered>
  <Example.Code>
    ```tsx
    <TextInput label="Label" message="Message" />
    ```
  </Example.Code>
</Example>

## Composition API

With the composition API, `TextField` manages the value and the ARIA wiring between the parts, and
you control the markup. For example, put the message below the input instead of above it:

<Example>
  <Example.Rendered>
    <TextField>
      <Label>Label</Label>
      <Input />
      <Message>Message</Message>
    </TextField>
  </Example.Rendered>
  <Example.Code>
    ```tsx
    <TextField>
      <Label>Label</Label>
      <Input />
      <Message>Message</Message>
    </TextField>
    ```
  </Example.Code>
</Example>

Or attach a button to the input:

<Example>
  <Example.Rendered>
    <TextField>
      <Label>Label</Label>
      <Message>Message</Message>
      <Group isMerged>
        <Input />
        <Button variant="border">Save</Button>
      </Group>
    </TextField>
  </Example.Rendered>
  <Example.Code>
    ```tsx
    <TextField>
      <Label>Label</Label>
      <Message>Message</Message>
      <Group isMerged>
        <Input />
        <Button variant="border">Save</Button>
      </Group>
    </TextField>
    ```
  </Example.Code>
</Example>

## Which to choose

| | Props API | Composition API |
| --- | --- | --- |
| Examples | `TextInput`, `NumberInput`, `CustomSelect`, `DatePicker` | `TextField`, `NumberField`, `SelectField`, `DateField` |
| Markup and layout | Fixed | Yours |
| Label, help text, error | `label`, `message`, `error` props | `<Label>`, `<Message>`, `<ErrorMessage>` children |
| Extra elements (buttons, icons) inside the field | Not supported | Any, with `Group` or `ComboInput` |
| Floating label variant | `variant="floating"` | Build it yourself |
| Used by `@atomicjolt/forms` | `Form.TextInput`, `Form.NumberInput`, ... | Composed fields with `Form.ErrorMessage` |

:::tip
Start with the props API. It covers most forms and keeps them consistent. Switch to the
composition API for a field that needs a layout the props API doesn't offer.
:::
