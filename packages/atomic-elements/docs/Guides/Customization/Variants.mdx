# Variants

Many components take a `variant` prop that picks a preset style or layout. There are two kinds:

- **Visual variants** change only the CSS. They're implemented with CSS custom properties, so you
  can restyle them or add your own without touching the library.
- **Structural variants** change the component's markup, such as a floating label. They're built
  into the component and can't be added from outside.

## Visual variants

`Button` (and `IconButton`) has these built-in visual variants:

`primary` is the default. A variant adds a class to the component's root element,
`aje-<component>--<variant>` (for buttons, `aje-btn--primary`), and that class sets the
component's tokens:

```css
/* The library's primary variant, simplified */
.aje-btn--primary {
  --btn-text-clr: var(--text-clr-on-accent);
  --btn-bg-clr: var(--accent-clr-fill);
  --btn-hover-text-clr: var(--btn-text-clr);
  --btn-hover-bg-clr: var(--accent-clr-fill-hover);
}
```

Each component's tokens are listed under **CSS variables** on its
[Storybook](https://atomicjolt.github.io/atomic-libs/storybook/?path=/docs/elements-buttons-button--overview)
page.

### Adding a visual variant

`variant` accepts any string, so a new variant is just CSS for a new class:

```css
.aje-btn--purple {
  --btn-bg-clr: purple;
  --btn-text-clr: white;
  --btn-hover-bg-clr: rgb(179, 13, 179);
  --btn-hover-text-clr: white;
}
```

<Example>
  <Example.Rendered
      style={{
        "--btn-bg-clr": "purple",
        "--btn-text-clr": "white",
        "--btn-hover-bg-clr": "rgb(179, 13, 179)",
        "--btn-hover-text-clr": "white",
      }}
  >
    <Button variant="purple">purple!</Button>
  </Example.Rendered>
  <Example.Code>
    ```tsx
    <Button variant="purple">purple!</Button>
    ```
  </Example.Code>
</Example>

Use tokens rather than fixed colors where you can (`var(--success-clr-fill)` rather than `green`),
so the variant follows the theme and works in the dark [color scheme](../../Theme/ColorSchemes.mdx).

### Changing a built-in variant

Override the same class. Component styles live in a [CSS layer](./CSSLayers.mdx), so a plain rule
in your own stylesheet wins without any extra specificity:

```css
.aje-btn--primary {
  --btn-bg-clr: hsl(220, 70%, 40%);
  --btn-hover-bg-clr: hsl(220, 70%, 32%);
}
```

To change it everywhere, prefer changing the tokens the variant reads instead (here
`accent-clr-fill` and `accent-clr-fill-hover`) in your [theme](../../Theme/Intro.mdx); that also
updates every other component that uses them.

:::note
If you turned layering off with `layerName={null}`, the library's selectors are more specific than
a single class, and you'll need a more specific selector (for example `.my-app .aje-btn--primary`)
to override them.
:::

## Structural variants

Structural variants change the markup. For example, the input components have a `floating`
variant, where the label sits inside the input and moves up when it has a value:

<Example>
  <Example.Rendered>
    <TextInput variant="default" label="Default variant" size="full" />
    <br />
    <TextInput variant="floating" label="Floating variant" size="full" />
  </Example.Rendered>
  <Example.Code>
    ```tsx
    <TextInput variant="default" label="Default variant" />
    <TextInput variant="floating" label="Floating variant" />
    ```
  </Example.Code>
</Example>

These components support `variant="floating"`:

- `TextInput`
- `NumberInput`
- `CustomSelect`
- `ComboBox`
- `MultiSelect`

For a layout that no variant provides, build the field yourself with the
[composition API](../Fields/CompositionVsProps.mdx).
