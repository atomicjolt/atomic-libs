# Collections

Many components display a list of items: `CustomSelect`, `MultiSelect`, `ComboBox`, `ListBox`,
`Menu` and `IconMenu`. They all describe their items the same way, using the
[React Aria collection API](https://react-spectrum.adobe.com/react-stately/collections.html):
`<Item>` and `<Section>` elements, or an `items` array with a render function.

`Item` and `Section` only describe the data. Each component decides how to render them, so the
same markup works in a select, a menu or a list box. `Table` and `Tabs` are built on the same
collection system but use their own part components (`Table.Row`, `Tabs.Tab`); see their Storybook
pages.

## Static collections

When the items are known ahead of time, write them as children:

### Item IDs

Give every item a unique `id`. It identifies the item in selection props and is what event
handlers receive:

```tsx
const [student, setStudent] = useState<Key | null>("sam");

<CustomSelect
  label="Student"
  selectedKey={student}
  onSelectionChange={setStudent}
>
  <Item id="david">David</Item>
  <Item id="sam">Sam</Item>
  <Item id="jane">Jane</Item>
</CustomSelect>
```

Components that allow several selections, such as `MultiSelect`, use `selectedKeys` /
`onSelectionChange` with a set of ids instead. Menus call `onAction(id)` when an item is chosen.

:::note Upgrading from v2
Items used to be identified by React's `key` prop. Use `id` instead; see
[Migrating](../Migrating.mdx#collection-components).
:::

## Dynamic collections

When the items come from data, pass the array as `items` and a render function as the child:

```tsx
const [animals, setAnimals] = useState([
  { id: "aardvark", name: "Aardvark" },
  { id: "kangaroo", name: "Kangaroo" },
  { id: "snake", name: "Snake" },
]);

<CustomSelect label="Animal" items={animals}>
  {(animal) => <Item id={animal.id}>{animal.name}</Item>}
</CustomSelect>
```

:::warning `items` must be objects
The collection caches rendered items in a `WeakMap` keyed by the item, and a `WeakMap` only
accepts objects. An array of strings throws:

```tsx
// Throws
<CustomSelect items={["David", "Sam", "Jane"]}>
  {(item) => <Item id={item}>{item}</Item>}
</CustomSelect>
```

Map the strings to objects first: `names.map((name) => ({ id: name, name }))`.
:::

### Why not `array.map`?

Mapping the array to children also works:

```tsx
<CustomSelect label="Animal">
  {animals.map((animal) => (
    <Item key={animal.id} id={animal.id}>
      {animal.name}
    </Item>
  ))}
</CustomSelect>
```

With `items` and a render function, though, the collection caches each rendered item and only
re-renders the items whose objects changed. That matters for large or frequently updated lists.

### Sections in dynamic collections

Sections take their own `items` and render function:

```tsx
const sections = [
  {
    name: "People",
    items: [{ name: "David" }, { name: "Sam" }, { name: "Jane" }],
  },
  {
    name: "Animals",
    items: [{ name: "Aardvark" }, { name: "Kangaroo" }, { name: "Snake" }],
  },
];

<CustomSelect label="Participant" items={sections}>
  {(section) => (
    <Section id={section.name} title={section.name} items={section.items}>
      {(item) => <Item id={item.name}>{item.name}</Item>}
    </Section>
  )}
</CustomSelect>
```

### Managing list data

For lists that change (adding, removing, filtering, loading more), Atomic Elements re-exports React
Stately's data hooks: `useListData`, `useAsyncList` and `useTreeData`. They keep the item array,
selection and filter text together:

```tsx
import { CustomSelect, Item, useListData } from "@atomicjolt/atomic-elements";

const list = useListData({
  initialItems: [
    { id: "aardvark", name: "Aardvark" },
    { id: "kangaroo", name: "Kangaroo" },
  ],
});

// Later: list.append({ id: "snake", name: "Snake" }); list.remove("aardvark");

<CustomSelect label="Animal" items={list.items}>
  {(animal) => <Item id={animal.id}>{animal.name}</Item>}
</CustomSelect>
```

See the [React Stately docs](https://react-spectrum.adobe.com/react-stately/useListData.html) for
their full APIs.

## Accessibility

When an item contains more than plain text (an icon, a badge, formatting), add `textValue` with a
plain-text version. It's used for type-ahead and read by screen readers:

```tsx
<Menu>
  <Item id="add" textValue="Add">
    <MaterialIcon icon="add" />
    Add
  </Item>
  <Item id="edit" textValue="Edit">
    <MaterialIcon icon="edit" />
    Edit
  </Item>
  <Item id="delete" textValue="Delete">
    <MaterialIcon icon="delete" />
    Delete
  </Item>
</Menu>
```
