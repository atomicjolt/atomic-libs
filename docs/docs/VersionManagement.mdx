# Version Management

Package versions and changelogs are managed with [Changesets](https://github.com/changesets/changesets).
Each change to a published package comes with a small markdown file in `.changeset/` that says which
packages it affects, how big the version bump is, and what to put in the changelog. At release time those
files are turned into version bumps and `CHANGELOG.md` entries.

## Adding a changeset

On your branch, after making the change:

```bash
npx changeset
```

The prompt asks which packages changed, whether each is a `major`, `minor` or `patch` change, and for a
summary. It writes a file like `.changeset/forms-new-input-wrappers.md`:

```md
---
"@atomicjolt/forms": minor
---

Add form wrappers for the rest of the atomic-elements inputs and fields: `Form.SearchInput`, ...
```

The summary becomes the changelog entry, so write it for people using the package. Commit the file with
your change. You can edit it by hand (or rename it) before merging.

Check what's pending, and the bumps it will produce, with:

```bash
npx changeset status
```

| Bump | Use for |
| --- | --- |
| `patch` | Bug fixes and internal changes that don't affect the API. |
| `minor` | New, backwards-compatible features (new components, props, exports). |
| `major` | Breaking changes (removed or renamed exports, changed behavior, raised peer dependency majors). |

### Changes that don't need one

Changes that don't affect any published package (docs, CI, the playground, repo tooling) don't need a
changeset; don't add an empty one. The changeset pre-push hook rejects branches that don't add a file to
`.changeset/` compared to `origin/main`, so push those branches with:

```bash
git push --no-verify
```

## Releasing

Releases are cut from `main`.

1. **Version.** Consume all pending changesets, bump package versions, write `CHANGELOG.md` entries, and
   bump internal dependents where needed:

   ```bash
   npx changeset version
   ```

   Review and commit the result (`.changeset` is configured with `commit: false`, so nothing is committed for you).

2. **Publish.** Build, then publish every package whose version isn't on npm yet:

   ```bash
   npm run build --workspaces
   npx changeset publish
   ```

   Packages are published with public access. `changeset publish` also creates a git tag per published
   package; push them with `git push --follow-tags`.
